# Admin PWA — install the admin as a home-screen app — Implementation Plan

**Goal:** The owner and staff can install **`/admin`** on Android or iPhone and open it
from a home-screen icon. It opens full-screen, with no browser bar, under the name **PMS
Admin**. If there is no signal, it shows a clear "You're offline" screen instead of a
browser error. **The public website is untouched:** it gets no manifest and no service
worker, and it isn't installable.

**Not in this package:** push notifications (follow-up **PWA-2**, below), offline editing,
and app-store listings (a Play Store TWA can wrap this later without code changes).

**Architecture:**

- **Web app manifest** `public/admin.webmanifest`, linked only from `admin.html`.
  `id`/`start_url` = `/admin`, `scope` = `/admin`, `display: standalone`, Rev 01
  graphite `#14171a` for `theme_color`/`background_color`, and icons generated from the
  PM monogram (`public/favicon.svg`).
- **Service worker** `public/admin-sw.js`, about 60 lines, **hand-written** with no
  Workbox or `vite-plugin-pwa`. It is served from the site root with the header
  `Service-Worker-Allowed: /admin` and registered with `scope: '/admin'`, so it can never
  control a public page.
- **Registered only from `src/admin/main.tsx`**, only in production builds, and only
  where `'serviceWorker' in navigator`.

**Tech stack:** React 19 + TS · Vite 6 (two HTML entries, ADR-0010) · Vercel headers ·
Vitest + RTL. One new dev dependency: `@resvg/resvg-js`, used only to render the icons.

## Decisions (for owner approval with this plan)

| Question | This plan | Why |
|---|---|---|
| Library or hand-written SW? | **Hand-written.** | `vite-plugin-pwa` assumes one entry. With vite-react-ssg plus a second `admin.html` it needs workarounds, and our caching needs are tiny. A short file we fully understand is safer. |
| Scope `/admin` or `/admin/`? | **`/admin`** (no trailing slash). | `cleanUrls` + `trailingSlash: false` serve the admin at `/admin`, which a `/admin/` scope would **not** cover. A `/admin` prefix also matches `/admin/jobs` etc. Nothing public starts with `/admin`. |
| What does the SW cache? | **Hashed `/assets/*` files: cache-first. Admin page loads: network-first, falling back to the last copy, then an offline page.** | Hashed files never change, so caching them is safe and makes launch fast. Network-first page loads mean a new deploy is picked up on the next open. |
| Supabase / API calls? | **Never touched by the SW.** Any request to another origin, or anything that isn't a GET, passes straight through. | No risk of stale data, cached sessions or cached private data. RLS and auth behave exactly as today. |
| App name | `name`: "Platinum Motor Services Admin" · `short_name`: **"PMS Admin"** | `short_name` appears under the icon. Home screens show about 12 characters. |
| Install button | A dismissible **"Install the app"** card on the **Dashboard**: a one-tap button on Android/desktop Chrome and Edge, and "Share → Add to Home Screen" steps on iPhone. Hidden once installed, or after "Not now". | Chrome offers install from its menu, but most people never find it. iOS has no install prompt at all. |
| Updates | The SW activates immediately (`skipWaiting` + `clients.claim`). Each deploy stamps a new cache version, and old caches are deleted. | No "refresh to update" step for a small team. Page loads are network-first anyway. |

## Global constraints

- **Branch** `feature/admin-pwa` from up-to-date `main`. Commits authored by the user
  only — **no `Co-Authored-By` trailer, no Claude PR footer**.
- **The public site must be byte-for-byte unaffected** apart from the new static files
  in `dist/`. No public HTML references the manifest or SW (checked by a build-time
  assert, Task 6).
- **CSP unchanged.** `manifest-src` and `worker-src` fall back to `default-src 'self'` /
  `script-src 'self'`, and every new file is same-origin.
- **Kill switch is documented** (Task 8) before merge.
- No database, Edge Function or env changes.

## Tasks

### Task 1 — App icons

- Add `scripts/gen-admin-icons.mjs`, which renders with `@resvg/resvg-js` (dev dependency):
  - `public/icons/admin-192.png`, `admin-512.png` — the favicon as-is (`purpose: any`).
  - `public/icons/admin-maskable-512.png` — **full-bleed** graphite with the monogram
    scaled to sit inside the central 80% safe zone (`purpose: maskable`), so Android's
    circle and squircle masks don't clip the letters.

- Commit the PNGs. The script is run by hand when the logo changes, not in `npm run build`.
- **Check:** open each PNG; test the maskable one at maskable.app.

### Task 3 — `admin.html` head

- `<link rel="apple-touch-icon" href="/icons/apple-touch-icon-180.png" />`
- `<meta name="apple-mobile-web-app-title" content="PMS Admin" />`

- Viewport gains `viewport-fit=cover` (needed for the safe-area insets in Task 7).
- The existing `theme-color` metas and the no-flash theme script stay as they are.

### Task 4 — Service worker `public/admin-sw.js`

Behaviour (the full code is written in the task):

- `const VERSION = '__BUILD_ID__';` → cache names `pms-admin-assets-<v>` and `pms-admin-pages-<v>`.
- **install:** pre-cache `/admin-offline.html` (Task 5), then `skipWaiting()`.
- **activate:** delete every `pms-admin-*` cache not on the current version, then `clients.claim()`.
- **fetch**, in order:
  1. Not a GET, or another origin (Supabase, Turnstile, analytics) → **don't handle it**.
  2. `request.mode === 'navigate'` and the path is in `/admin` → **network-first**. On
     success, store a copy under the key `/admin`. On failure, serve the cached `/admin`,
     else `/admin-offline.html`.
  3. Path starts with `/assets/` → **cache-first**, filled on use (only `ok` responses).
  4. Anything else → don't handle it.
- Keep the routing decision in a **pure function** `route(url, method, mode)` returning
  `'skip' | 'page' | 'asset'`, mirrored in `src/admin/pwa/route.ts` so it can be unit-tested.
  A test asserts both copies agree on a table of URLs.

**Build stamp:** extend `scripts/strip-admin-preload.mjs` (it already post-processes
`dist/`), or add a new `scripts/stamp-admin-sw.mjs` to `npm run build`, to replace
`__BUILD_ID__` in `dist/admin-sw.js` with `VERCEL_GIT_COMMIT_SHA` (local fallback:
timestamp). It fails the build if the placeholder isn't found.

### Task 5 — Offline page `public/admin-offline.html`

A self-contained static page with inline styles: graphite background, the PM monogram
inlined, "You're offline", "PMS Admin needs a connection to load your jobs and
bookings.", and a **Try again** button (`location.reload()`). It follows the system light
or dark theme via `prefers-color-scheme`. `noindex`.

### Task 6 — Register the SW and the Vercel headers

- `src/admin/pwa/register.ts`: `registerAdminServiceWorker()` returns early unless
  `import.meta.env.PROD && 'serviceWorker' in navigator`. On `load` it calls
  `navigator.serviceWorker.register('/admin-sw.js', { scope: '/admin' })`, and errors
  are logged, never thrown.
- Call it from `src/admin/main.tsx` after `render`.
- `vercel.json` headers:
  - `/admin-sw.js` → `Cache-Control: no-cache` and `Service-Worker-Allowed: /admin`
  - `/admin.webmanifest` → `Content-Type: application/manifest+json`
  - `/icons/(.*)` → `Cache-Control: public, max-age=604800`
- **Build-time assert** (in `scripts/check-content.mjs`): no `dist/**/*.html` other than
  `admin.html` and `admin-offline.html` mentions `admin.webmanifest` or `admin-sw.js`.
- **Tests:** `register.test.ts` checks it doesn't register in dev, doesn't register when
  `serviceWorker` is missing, and registers with scope `/admin` in prod. `route.test.ts`
  covers the routing table (Supabase URL → skip, POST → skip, `/admin/jobs` navigate →
  page, `/assets/admin-x.js` → asset, `/` navigate → skip, `/services` → skip).

### Task 7 — Install card and standalone polish

- `src/admin/pwa/useInstallPrompt.ts`: captures `beforeinstallprompt` (and prevents the
  mini-infobar), and exposes `{ canPrompt, prompt(), isStandalone, isIos }`.
  `isStandalone` = `matchMedia('(display-mode: standalone)')` or
  `navigator.standalone`.
- `src/admin/components/InstallAppCard.tsx` on the **Dashboard**:
  - Hidden if standalone, or if dismissed (`localStorage['pms-install-dismissed']`, in
    try/catch).
  - Android/desktop with `canPrompt` → **Install the app** button + **Not now**.
  - iOS Safari → "Tap **Share** ⎋ then **Add to Home Screen**" + **Not now**.
  - Otherwise (Firefox, or iOS in Chrome) → hidden.
- Safe areas in standalone on iPhone: the sticky admin header gets
  `padding-top: env(safe-area-inset-top)` and its height grows to match. The fixed
  sidebar/backdrop `top-16` offsets use the same calc. The bottom of the sidebar gets
  `env(safe-area-inset-bottom)`.
- **Tests:** InstallAppCard renders nothing when standalone, shows iOS steps on an iOS
  UA, shows the button when `canPrompt`, and "Not now" hides it and remembers.

### Task 8 — Docs

- `docs/owner-guide.md`: a new section **"Install the admin on your phone"**. Android:
  open `/admin` in Chrome → **Install the app** (or ⋮ → Install app). iPhone: open in
  **Safari** → Share → Add to Home Screen. Includes the notes below.
- `docs/decisions.md`: ADR for "Admin PWA, hand-written SW scoped to `/admin`".
- **Kill switch** (in the ADR): if the SW ever misbehaves, replace
  `public/admin-sw.js` with a version that, on `activate`, deletes all `pms-admin-*`
  caches and calls `self.registration.unregister()`. Deploy it, and every installed copy
  cleans itself up on next open.

## Things to know (put in the owner guide)

- **iPhone keeps the app's login separate from Safari's.** Everyone signs in once inside
  the installed app.
- **Email links (invites, password resets) open in the browser, not the app.** Finish
  there, then open the app and sign in.
- **The app is the website.** Every deploy updates it on next open. There's nothing to
  reinstall and no store review.
- **iOS must use Safari** to install. Chrome on iPhone can't add web apps to the home
  screen with the full app experience.

## Verification (before merge)

1. `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. The new build-time
   assert passes.
2. `npm run preview` → Chrome DevTools → **Application**: the manifest loads with no
   errors and the icons show. The SW is **activated** with scope `https://…/admin`.
   **Public pages show no SW.**
3. DevTools → Network → **Offline**, then reload `/admin/jobs`: the cached admin or the
   offline page appears, never Chrome's dinosaur. Offline on `/`: the normal browser
   error (the public site isn't controlled).
4. Vercel preview deploy:
   - **Android Chrome:** install from the card, launch from the icon (standalone, graphite
     splash with the PM icon), sign in, open a job, kill the app and reopen it.
   - **iPhone Safari:** Add to Home Screen. The icon and name are right, the header isn't
     under the notch, and you can sign in and navigate.
5. Deploy again with a trivial change and reopen the installed app: the new version loads
   with no manual refresh.
